# 08. マルチエージェント運用（Claude Code subagents）

## 何を変えたか
アプリ本体（`backend/`, `frontend/`）は **一切変えていない**。追加したのは Claude Code の運用設定だけ。

```
CLAUDE.md                 司令塔（メイン agent）の指示書: プロジェクト構成・コマンド・不変条件・委譲ルール
.claude/agents/
  analyst.md              動画・編集傾向分析（読み取り専用, sonnet）
  editor.md               編集処理の実装・変更（書き込み可, メインと同モデル）
  qa.md                   品質チェック（テスト/出力検証/不変条件監査, sonnet）
  improver.md             改善: 人間修正・所見 → プロンプト/DNA/ルール更新（書き込み可, メインと同モデル）
docs/08_…                 このドキュメント
```

## 有効化の注意
`.claude/agents/*.md` は **Claude Code のセッション開始時に読み込まれる**。追加・変更した直後の同一セッションでは `subagent_type: editor` 等が見つからない（実際、導入テストでは `general-purpose` に指示書を読ませて代用した）。新しいセッションを開けばそのまま使える。

## 運用モデル
- ユーザーはメイン agent（Claude Code のセッション）にだけ話す。agent ごとの指示は出さない
- メイン agent = 司令塔。タスクを分解し、**独立していて並列化できるものだけ** を subagent に委譲。逐次依存・単純作業・1〜2 ファイルの修正は自分でやる
- 4 役は基本形であって固定ではない。仕事の無い役は起動しない。役に無い専門性は `general-purpose` に指示書を渡す
- 並列 agent は書き込み範囲を分けて衝突を防ぐ（editor 2 体なら別ディレクトリ）
- 編集系 agent の報告は qa（または司令塔自身の pytest）で裏取りしてから採用

### 委譲判断の表
| 状況 | 誰がやる |
|---|---|
| 現状把握（ファイルを数個読む） | 司令塔 |
| 候補の質・傾向・原価の評価（数字が要る） | analyst |
| パイプライン / 画面の機能追加（互いに独立な複数件） | editor × N（並列、範囲分割） |
| 1 ファイルのバグ修正 | 司令塔 |
| 変更後の合否判定、出力 MP4 の検証 | qa |
| 人間の修正が溜まった → プロンプト / ルール更新 | improver |
| commit / push / ユーザーへの報告 | 司令塔 |

## 導入テスト（2026-09-18 実施）
テストシナリオ: 「字幕アニメ `typewriter` が `CaptionStyle` の選択肢にあるのに未実装」という実タスクで、司令塔が分解して委譲。

| 順序 | agent | 担当 | 結果 |
|---|---|---|---|
| 並列① | analyst | 現在の候補選定プロンプトと Phase1 出力を読み、Phase 2 に向けた評価軸の不足を数字で指摘 | 下記「結果ログ」参照 |
| 並列② | editor | `providers/caption/ass_caption.py` に typewriter を実装し、合成動画で検証 | 〃 |
| 逐次③ | qa | editor 完了後に pytest + 出力 MP4 + 不変条件監査 | 〃 |
| 未起動 | improver | 人間の修正ログ（HumanEdit）がまだ無いので起動しない（「必要な agent だけ」の実証） | – |

結果ログは司令塔の報告（セッションのチャット）に記載。以後のテストもこの表に追記していく。
