# 02. データ構造

DB は SQLite（`data/app.db`、SQLModel）。JSON 列には `backend/app/schemas/*.py` の Pydantic モデルをそのまま入れる。
**Creator ごとに完全分離**: 全テーブルが `creator_id` を持ち、DNA・辞書・原価・修正履歴は他 Creator と混ざらない。

```
Creator ──1:N── Video ──1:1── Transcript
   │              │
   │              ├──1:N── Candidate ──1:N── Export (edit_plan = EDL)
   │              │
   │              └──1:N── Job
   ├──1:N── CostEntry (video_id, job_id も持つ)
   └──1:N── HumanEdit (candidate_id / export_id)
```

## テーブル

| テーブル | 主要列 | 役割 |
|---|---|---|
| `creator` | name, notes, **dictionary(JSON)**, **creator_dna(JSON)**, **editing_dna(JSON)**, caption_style(JSON) | Profile。DNA は Phase2/3 で埋まる |
| `video` | creator_id, path, duration/width/height/fps, status | 長尺の元動画 |
| `transcript` | video_id, provider, model, **data(JSON=TranscriptData)** | segments[words[]]、話者、音声イベント |
| `candidate` | video_id, rank, start_sec, end_sec, score, title, **data(JSON=ShortsCandidate)**, decision | Shorts 候補。decision = 人間の採用/却下（Phase5 の学習データ） |
| `export` | candidate_id, status, path, **edit_plan(JSON=EditPlan)** | 完成品と「AI が下した判断の列」。人間修正との diff 基準 |
| `job` | kind(analyze/export), status, stage, progress, message, error, payload, result | 進捗表示 |
| `cost_entry` | creator_id, video_id, job_id, category, provider, model, quantity, unit, usd, meta | 原価台帳（動画単位/Creator単位で集計） |
| `human_edit` | creator_id, action, before, after, inferred_reason | Phase5 の修正ログ。Phase1 では候補の採用/却下のみ |

## 共通スキーマ

### TranscriptData（`schemas/transcript.py`）
```
TranscriptData { language, duration, provider, model, vocabulary_hint[],
  segments: [ Segment { id, start, end, text, speaker?, events[], words: [ Word { text, start, end, confidence? } ] } ] }
```
- `as_timed_lines()` … LLM に渡す `[mm:ss.s-mm:ss.s] 本文` 形式
- `words_between(start,end)` … 字幕用。単語TSが無い Provider でも文字を等分配して返す

### ShortsCandidate（`schemas/candidates.py`）= LLM の構造化出力
```
{ start_sec, end_sec, title, title_alternatives[2], summary, hook(原文引用), hook_suggestion,
  why_clip, creator_likeness_reason, standalone_ok, standalone_reason, retention_reason,
  scores { hook_strength, standalone, creator_likeness, retention, payoff, past_shorts_similarity }, score, tags[] }
```
要求仕様の「開始/終了/尺/内容/冒頭フック/タイトル案/価値/らしさ/単体成立/視聴維持/スコア」に 1:1 対応。
